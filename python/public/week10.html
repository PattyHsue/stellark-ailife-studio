Exceptions are not failures — they are structured messages from your program about unexpected conditions. Writing robust error handling is what separates professional-grade software from fragile scripts.例外（Exception）不是失敗，而是程式面對意外狀況時發出的結構化訊號。撰寫健壯的錯誤處理機制，是區分專業級工業軟體與脆弱腳本的關鍵分水嶺。

📝 10 Knowledge Quizzes📝 10 題隨堂知識測驗

  1. What is the main purpose of a `try / except` block?`try / except` 區塊最主要的用途是什麼？
    💡 Answer: To catch and handle runtime errors gracefully so the program can recover instead of crashing.💡 參考解答：優雅地攔截並處理執行期錯誤（Runtime Errors），讓程式能給出友善提示並繼續運作，而不會直接崩潰閃退。
  2. In a `try / except / else / finally` structure, when does the `else` block run?在 `try / except / else / finally` 結構中，`else` 區塊什麼時候才會執行？
    💡 Answer: Only when NO exception was raised inside the `try` block.💡 參考解答：只有在 `try` 區塊內「完全沒有發生任何例外錯誤」時才會執行。
  3. When does the `finally` block run?`finally` 區塊什麼時候會執行？
    💡 Answer: ALWAYS — whether an exception occurred, was caught, or not. Ideal for closing files or releasing resources.💡 參考解答：永遠都會執行！無論有沒有發生錯誤、錯誤有沒有被捕捉，`finally` 都會執行，最適合用來釋放資源或關閉連線。
  4. What does `raise ValueError('Invalid score')` do?`raise ValueError('Invalid score')` 的作用是什麼？
    💡 Answer: Manually triggers (raises) a `ValueError` exception with the specified custom message.💡 參考解答：主動拋出一個帶有自訂錯誤訊息 `'Invalid score'` 的 `ValueError` 例外。
  5. How do you define a custom exception class in Python?在 Python 中如何自訂一個專屬的例外錯誤類別？
    💡 Answer: Create a class that inherits from `Exception`, e.g., `class MyCustomError(Exception): pass`.💡 參考解答：定義一個繼承自 `Exception` 的類別，例如：`class MyCustomError(Exception): pass`。
  6. What does `except Exception as e:` capture?`except Exception as e:` 中的 `as e` 代表什麼？
    💡 Answer: Captures the exception instance into variable `e`, allowing you to inspect or log the exact error message.💡 參考解答：將捕捉到的例外錯誤物件存入變數 `e` 中，方便印出或記錄詳細的錯誤原因。
  7. What is the difference between `ValueError` and `TypeError`?`ValueError` 與 `TypeError` 的差異是什麼？
    💡 Answer: `ValueError` occurs when the type is valid but the content is inappropriate (e.g. `int('abc')`); `TypeError` occurs when the data type itself is incompatible (e.g. `int(None)` or `'a' + 1`).💡 參考解答：`ValueError` 是資料型別正確但「內容值不合法」（如 `int('abc')`）；`TypeError` 則是「資料型別本身不相容」（如 `'a' + 1`）。
  8. What does `assert x > 0, 'x must be positive'` do?`assert x > 0, 'x must be positive'` 的作用是什麼？
    💡 Answer: Checks if `x > 0` is True; if False, it immediately raises an `AssertionError` with the message.💡 參考解答：檢查 `x > 0` 是否成立；若為 `False`，則立即拋出 `AssertionError` 並顯示提示訊息，常用於開發階段的自我檢測。
  9. What is the Retry Pattern in error handling?什麼是錯誤處理中的「重試模式（Retry Pattern）」？
    💡 Answer: Wrapping an operation inside a loop with `try / except` so transient failures are retried up to N times before failing.💡 參考解答：將可能暫時失敗的操作（如網路連線或使用者輸入）包在迴圈與 `try/except` 中，允許自動重試數次。
  10. Why is writing a bare `except:` without specifying an error type considered bad practice?為什麼不指定錯誤型別而單寫 `except:` 被視為不良的工程習慣？
    💡 Answer: Because it silently swallows ALL exceptions (including `KeyboardInterrupt` and typos), making debugging very difficult.💡 參考解答：因為它會無差別吞掉所有錯誤（包含系統中斷與打字拼寫錯誤），導致真正的 Bug 被掩蓋而難以除錯。
